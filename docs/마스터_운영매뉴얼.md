# 로켓그로스 운영 마스터 매뉴얼

버전: 2026.10.27-v1

현재 연결된 자료의 해석·점검 절차입니다. 쿠팡 정책 또는 업무 전체를 보장하는 공식 매뉴얼이 아닙니다.

이 문서는 일반적인 운영 점검 절차입니다. 각 지표의 집계기간과 원본 시각을 먼저 확인하세요.

## 자료 검증부터 시작

점검 시점: 매일 운영 시작 전과 새로고침 직후

### 점검 순서

1. 자료실에서 마지막 성공 시각과 이번 수집 상태를 함께 확인합니다.
2. 원본 파일의 조회기간·SKU 등급·VAT 포함 여부를 확인합니다.
3. API 옵션, 재고 엑셀의 SKU·등급 행, 주문 건수를 서로 다른 범위로 기록합니다.
4. 전일과 비교하려면 같은 기간 길이와 집계 기준의 원본을 준비합니다.

### 판단 보류 조건

- 갱신 실패·원본 열 변경·합계 불일치가 있으면 해당 숫자를 최신값으로 사용하지 않습니다.
- 비어 있는 값을 매출 없음·재고 없음·보상 없음으로 바꾸지 않습니다.

완료 기준: 사용한 원본과 기간을 확인하고, 미수집 항목을 남겼습니다.

근거 자료 ID: api_orders, inventory, finance

## 재고·입고 판단

점검 시점: 품절 또는 입고 검토 후보가 있을 때

### 점검 순서

1. 권장 입고량·예상 재고일을 후보 목록으로 확인합니다.
2. API와 엑셀에서 옵션 ID와 상품등급을 맞춰 판매가능재고를 대조합니다.
3. 실제 조달기간·이미 예약한 입고·최소 발주량을 확인합니다.
4. 후보별 수량과 자금 부담을 검토한 뒤 직접 발주 여부를 결정합니다.

### 판단 보류 조건

- 권장 입고량은 자동 발주 지시가 아닙니다.
- 실제 조달기간이나 재고 시점이 확인되지 않으면 발주 확정을 보류합니다.

완료 기준: 입고 후보의 현재 재고와 실제 조달기간을 대조했습니다.

근거 자료 ID: inventory, api_inventory

## 광고·원가 점검

점검 시점: 광고비 또는 ROAS가 걱정될 때

### 점검 순서

1. 상품 매입원가·기타 단위비용부터 입력합니다.
2. 광고 성과 보고서의 집계기간과 전환 기여기간을 확인합니다.
3. 캠페인·상품별 광고비와 같은 기간의 수수료·환불을 대조합니다.
4. 작게 변경할 후보와 관찰 종료일을 정하고 변경 전 수치를 남깁니다.

### 판단 보류 조건

- 원가가 없으면 손익분기 ROAS나 순이익을 확정하지 않습니다.
- 정산 매출과 광고 전환매출을 합산하지 않습니다.
- 최근 광고 전환은 뒤늦게 반영될 수 있어 하락 원인을 단정하지 않습니다.

완료 기준: 원가와 동일 기준 광고 상세를 확보한 뒤 변경 근거를 기록했습니다.

근거 자료 ID: ads, ad_detail, inventory

## 정산·현금 흐름 확인

점검 시점: 정산일 전후와 월 마감 때

### 점검 순서

1. 윙 수익 현황의 조회기간과 수집 시각을 확인합니다.
2. 매출 + 비용(음수) + 보상 = 윙 표시 이익인지 대조합니다.
3. 정산 상세의 정산주기 종료일과 VAT 포함 최종비용을 확인합니다.
4. 빠른정산·보류·지급비율을 확인하고 실제 입금 내역과 별도로 대조합니다.

### 판단 보류 조건

- 윙 표시 이익에는 사입원가 등 외부 비용이 빠져 있으므로 순이익으로 쓰지 않습니다.
- 정산주기 비용을 다른 기간의 월간 비용에 다시 더하지 않습니다.
- 월말 미포함 보상액으로 해당 월 보상 유무를 판단하지 않습니다.

완료 기준: 조회기간·정산주기·실제 입금의 차이를 확인했습니다.

근거 자료 ID: finance, settlement

## 반품·보상 확인

점검 시점: 장기 회수중이거나 반품 사유가 반복될 때

### 점검 순서

1. 접수일과 원본 처리 상태로 장기 회수 후보를 확인합니다.
2. 쿠팡윙에서 현재 회수 상태를 재확인합니다.
3. 보상 원본의 주문·옵션·정산주기를 로컬에서 대조합니다.
4. 이미 처리된 건을 제외하고 상태·보상 반영 여부를 문의합니다.
5. 월별 반품률과 상품별 반품 사유로 상세페이지 개선 후보를 검토합니다.

### 판단 보류 조건

- 90일 이상 회수중은 미보상 확정이나 지급액 추정이 아닙니다.
- 누적 반품 접수 건수를 현재 주문·매출로 나눠 반품률을 만들지 않습니다.
- 주문번호·고객정보가 있는 원본을 외부 AI에 보내지 않습니다.

완료 기준: 현재 처리 상태와 보상 반영 여부를 대조해 확인 대상을 추렸습니다.

근거 자료 ID: returns, return_insight, compensation

## 주간 점검과 다음 계획

점검 시점: 주간 검토와 다음 주 계획 수립 때

### 점검 순서

1. 자료별 조회기간을 맞추고 이번 주에 확보하지 못한 원본을 기록합니다.
2. 원가·입고 후보·장기 회수 상태의 미완료 항목을 확인합니다.
3. AI 제안에서 관측 근거와 가설을 구분하고 추가 확인 자료를 준비합니다.
4. 작업별 담당자·완료 기준·실제 결과를 기록하고 다음 점검일에 검토합니다.

### 판단 보류 조건

- 자료가 부족한 주제는 확인 작업으로 남기고 원인이나 성과를 꾸며 내지 않습니다.
- AI는 실행 제안이며 광고 변경·발주·가격 수정은 직접 검토합니다.

완료 기준: 검증된 사실, 미확인 가설, 다음 확인 작업을 구분해 기록했습니다.

근거 자료 ID: inventory, ads, finance, returns

## 지표 정의와 제한

- 매출·윙 표시 이익·실제 입금액은 서로 다릅니다.
- 권장 입고량은 발주 확정이 아닙니다. 미입력 리드타임은 경보 계산용 기본값을 사용하므로 실제 조달기간을 확인합니다.
- 최근 수집은 데이터 자체의 실시간성을 보장하지 않습니다.
- 고객·주문 식별정보는 AI 입력에서 제외합니다. 원본은 본인 전용 자료실에서 보관합니다.
- AI가 작성한 실행 제안은 실제 성과를 보장하지 않습니다.
